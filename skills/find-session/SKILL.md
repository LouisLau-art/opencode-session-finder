# 找历史会话

工具已经装好：`/usr/local/bin/ocs`，只读打开 `~/.local/share/opencode/opencode.db`（root 与 louis 共用同一份二进制）。

## 为什么不用 `opencode session list`

OpenCode 按**启动目录**把会话归到不同 project，`opencode session list` 只列当前目录那一个 project 的东西。用户要找的会话大概率在别的目录（`~/Projects/feishu-docs`、`~/Projects/qinkung` …），所以那个命令天然看不见。`ocs` 直读数据库，跨全部 project。

## 流程

### 1. 从用户的话里抽关键词

- 用**实体词**：产品名、报错码、文件名、英文缩写、人名、表名。用户怎么说就怎么搜，不要先翻译或改写。
- 优先**稀有词**。`妙搭` 会命中几十个会话，`CN-CLIP` 可能只命中 3 个；稀有词一个顶十个常见词。
- 用户给的是描述而不是词（"那个做视频检索的"）时，先想他当时可能用的英文/产品名，再搜。

### 2. 搜

```sh
ocs find <词1> <词2> --json -n 10
```

- 词与词之间是「每个词都要在这个会话里出现过」，但**不要求落在同一条消息**——一个话题往往跨好几轮。
- 排序：覆盖了几个词 → 词频（取过对数，防止某个词刷屏）→ 时间新旧。
- 单次全库扫描约 1 秒，可以放心多搜几轮。
- `--json` 返回 `hit_counts` / `snippets` / `resume_cmd` / `covered`，比人读版更好挑。

### 3. 搜不到就换词，不要急着说「没有」

用户记住的词和会话里实际写的词经常不是同一个：

- 同义：局限 / 限制 / 缺点 / 边界；报错 / 异常 / 失败 / 卡住
- 换语言：妙搭 / Spark / Miaoda / lark-apps；聚水潭 / JST / erp321
- 加时间窗：`--since 30d`、`--since 2w`

关键词只在正文里、标题里没有，这正是必须搜正文的原因。

### 4. 词实在想不起来，就按时间捞

```sh
ocs list -n 40 --json
```

按日期 + 目录 + 标题扫一遍。用户说「大概是上周」的时候直接切这里，比硬猜词快。

### 5. 候选不止一个 → 问用户

用 `question` 工具把 2-5 个候选列出来（标题 + 日期 + 目录 + 一句命中理由）让用户点。不要自己挑一个就当答案往下做。

### 6. 打开

```sh
ocs show <ID前缀或标题片段> --md   # 读全文
ocs open <ID>                      # 只要续接命令
```

`show` 接受完整 ID、`ses_` 前缀、ID 中段、标题子串；匹配到多个会列出候选。

## 回答用户时的格式

一条会话一段，至少包含：**标题、日期、目录、为什么是它**（引一句命中片段）、续接命令。让用户能一眼判断是不是，并且能直接跳进去。

## 坑

- 说「没找到」之前必须至少换过一轮同义词、并且跑过一次 `list`。直接下负面结论是最容易错的地方。
- 只读。不要用 `sqlite3` 或别的工具直接写这个库。
- 会话内容里中文是原样 UTF-8，不是 `\uXXXX`，所以中文关键词能直接命中。
